## 운영 V2 배치

아래는 2026-11-02 갱신된 운영 문서에 기록된 구성입니다. 이번 사이트 갱신에서 호스트 상태를 새로 조사한 결과는 아닙니다.

| 역할 | 호스트·사양 | 실행 대상 |
| --- | --- | --- |
| 서버 | `catus-prod-V2` · m6g.large | nginx, Business, Data, Realtime, Notification |
| Kafka | `catus-kafka-prod-V2` · m6g.medium | Kafka 3.8.1 |
| Redis | `catus-redis-prod-V2` · m6g.medium | Redis 7.4.11 Shared·Business 두 인스턴스 |
| 백오피스 | `catus-backoffice-prod-V2` · t4g.small | 운영 관리 웹 |
| DB | RDS `catus-prod-db` · db.t4g.small | 기존 운영 DB를 V2가 계속 사용 |

`catus-prod-db-v2`는 별도로 준비되어 있지만 위 기록에서는 아직 사용하지 않습니다. V2라는 이름만 보고 사용 DB가 바뀌었다고 판단하지 않습니다.

## 공개 경로

공개 API 주소는 `catus-api-v2.oneorthree.world`, 백오피스는 `backoffice-v2.oneorthree.world`입니다. HTTP는 Business, WSS는 Realtime으로 전달됩니다. Data 내부 API와 관리 포트를 앱의 공개 진입점으로 사용하지 않습니다.

구 `api`, `catus-api`, `focuscat-api`, `link` DNS는 11월 2일 삭제한 것으로 기록돼 있습니다. `backoffice.oneorthree.world`는 V2 백오피스로 302 이동합니다. 과거 문서의 주소로 새 환경을 구성하지 않습니다.

## dev V2 배치

| GCP VM | 사양 | 실행 대상 |
| --- | --- | --- |
| `catus-dev-v2-app` | e2-medium | nginx와 서버 4종 |
| `catus-dev-v2-data` | e2-small | PostgreSQL 16.14와 Kafka 3.8.1 |
| `catus-dev-v2-redis` | e2-micro | Shared·Business Redis 7.4.11 |

공개 주소는 `oneorthree-v2.dev.mooo.com`입니다. main 변경은 해당 CI와 `cd-auto.dev-v2.yml`을 통해 자동 배포됩니다. dev 백오피스는 없으며 구 `gromo-dev-app` VM·디스크·러너 등록은 삭제됐습니다.

## Redis와 관측

운영 Redis의 `maxmemory`는 Shared 384MB, Business 128MB이고 둘 다 `noeviction`·AOF를 사용합니다. dev의 한도는 이보다 작습니다. 컨테이너 메모리 한도와 Redis `maxmemory`는 같은 값이 아닙니다.

운영 문서는 11월 2일 EC2 4대에서 Datadog Agent health를 확인했다고 기록합니다. 이는 Datadog 화면의 최신 로그·APM 수신 확인과 다릅니다. dev V2의 세 VM에는 Datadog Agent를 설치하지 않습니다. Fluent Bit·Loki·S3 경로는 관측 rollout과 실제 배포 설정을 함께 봅니다.

## 파일 소유권과 배포

AWS 자원·SSM·서버 및 백오피스 Compose·env 계약은 `cattus-infra/prod/catus-v2/`가 소유합니다. Kafka·Redis Compose는 phone의 `server/scripts/v2/prod/`, 발행·배포는 `.github/scripts/v2/prod/catus-runtime-V2.py`가 담당합니다.

서버·Kafka·Redis는 release 발행 후 수동 CD, 백오피스는 main 머지 후 환경 승인 배포입니다. 절차와 복구 제한은 [V2 배포 안내](/operations/06-v2-deployment)를 따릅니다.
