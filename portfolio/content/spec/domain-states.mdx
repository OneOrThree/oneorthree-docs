| 도메인 | 상태·전환 | 누가 바꾸나 |
| --- | --- | --- |
| 집중 세션 | `ACTIVE ↔ PAUSED → 종료`, 방치 시 `ABANDONED` | 사용자 명령, 앱의 이탈 판정, 서버 방치 종결 |
| 섬 통장 | 적립(집중·퀘스트) / 지출(건설·상점·잡지 홍보) | 서버 원장 |

| 꾸미기 지급·추첨 풀 | `미리 계산 → 승인 → 다른 운영자가 실행·발행` | 백오피스 운영자 2명 |
| 신고 | `접수 → 종결(RESOLVED·DISMISSED) → 30일 뒤 파기` | 사용자가 접수, 운영팀이 종결 |

## 집중 세션

섬 집중과 바다 집중은 세션 kind로 구분합니다. 집중·휴식·종료 전환을 서버가 관리하고, 집중 구간의 유효 시간으로 정산합니다. 휴식은 세션을 삭제하는 동작이 아니며 이미 쌓인 유효 집중을 없애지 않습니다. 휴식 중에는 적립과 황금 추첨이 멈춥니다.

| 상황 | 처리 |
| --- | --- |
| 차단·복귀가 걸리지 않은 섬 집중에서 앱을 나감 | 앱이 `pause`를 보낸다. 15초 안에 돌아오면 `resume`, 넘기면 휴식 상태에서 `finish` |
| 나간 채 앱이 꺼짐 | 다음 실행에서 같은 기준으로 판정 |
| 휴식이 1시간 이어짐 | 서버가 닫는다 |
| 마지막 시작·재개 뒤 섬 12시간·바다 3시간이 지난 `ACTIVE` | 서버가 `ABANDONED`로 닫는다. 정산·기록·순위 가산·보상은 없고, 이미 섬 통장에 들어간 물고기는 회수하지 않는다 |

앱의 연결 끊김, 화면 타이머, 웹소켓 presence는 세션의 최종 상태와 다릅니다. 재접속 시 현재 세션을 조회하고, 서버의 생존·종료·정산 규칙에 맞춰 복구합니다. 중복 시작·종료와 자정 경계는 서버 계약에서 처리합니다.

AI 집중 측정의 판정은 앱 안에서 하는 인증 시간 측정이며 세션 상태를 바꾸지 않습니다. 측정이 불가능하다고 확정된 기기에서는 그 세션 동안 주기 측정을 멈추고, 새 세션에서 다시 시도합니다.

## 물고기와 원장

물고기는 섬 통장 소유입니다. 집중 적립과 퀘스트 보상, 건설·상품 구매·잡지 홍보(60마리) 지출은 각각 원장과 중복 방지 키를 통해 반영됩니다. 잔액을 앱이 계산해 지급하거나 소비 결과를 확정하지 않습니다.

집중 분의 적립일은 해당 분이 완성된 UTC 날짜를 사용합니다. 기록 화면의 날짜 축과 섬 적립 날짜를 같은 것으로 취급하지 않습니다. [재화 경계 결정](/adr/adr-035-village-economy-boundaries)

## 건설

`목표 선택 → 건설 시작 → 공사 중 → 완공`을 구분합니다. 목표 선택은 차감 0이고, 착공 순간 잠긴 섬 통장에서 총 건설비를 한 번 차감합니다.

- 모든 건물의 모금 방식은 섬 통장 합산(`WALLET_TOTAL`)입니다(V14). 주민별 할당량·목표 선택 시각·기여 인원은 착공 조건이 아닙니다. 응답의 `residentProgress`는 이전 앱 호환용으로 남고 `null`입니다.
- 가격·공사 시간·섬장 권한·선행 시설·동시 공사 1건 제한은 유지합니다.
- 새 섬은 마을회관 완공 상태로 만들어집니다. 회관은 건물 트리의 뿌리입니다.

목표 선택·착공은 섬장 권한입니다. 상품 공동 구매 권한과 건설 권한을 하나로 묶지 않습니다. 완공 뒤 열리는 조회·명령도 시설별로 다릅니다.

## 퀘스트

퀘스트는 섬장이 만들고, 서버가 회차를 열어 주민의 달성을 판정합니다. 주민은 자기 몫(+10마리)을 받고, 그 처리에서 전원 달성이 처음 확인되면 보너스(대상 주민 수 × 5마리)가 함께 섬 통장에 들어갑니다. 출시 스위치는 코드에서 없앴습니다.

main에만 있고 운영 서버에 아직 없는 규칙(V17):

- **삭제**는 소프트 삭제(`deleted_at`)입니다. 열린 회차도 목록에서 빠지고 받기·수정은 404입니다. 다음 회차를 열지 않고, 그 회차의 전원 보너스도 정산하지 않습니다. 이미 받은 보상은 되돌리지 않습니다.
- **시간대 겹침 금지**: 판정이 퀘스트마다 독립이라 겹친 시간대는 한 번의 집중으로 여러 퀘스트를 채웁니다. 그래서 같은 섬의 지우지 않은 집중 퀘스트와 겹치면 생성을 409로 거절합니다. 이미 겹쳐 있던 퀘스트는 섬장이 삭제로 정리합니다.

## 상점과 꾸미기

상점은 활성 발행본에 가격이 있는 상품만 팝니다. 꾸미기 카탈로그에 그림이 없는 개인 꾸미기는 목록에서 빠지고, 상세·구매는 이미 가졌는지와 관계없이 404입니다(차감 0).

운영자가 꾸미기를 지급하거나 집중 보상 추첨 풀을 바꾸는 일은 2인 승인입니다. 승인자와 실행·발행자는 달라야 하며 DB 제약으로도 막습니다. 추첨 풀 변경은 기존 정책을 고치지 않고 새 revision을 발행합니다. 지난 정산이 이전 revision을 참조하기 때문입니다.

## 주민과 연락 권한

가입·탈퇴·강퇴·섬장 위임은 Data의 현재 주민 자격을 바꿉니다. Realtime 캐시와 presence는 후속 반영 창이 있으므로 최종 자격으로 사용하지 않습니다.

친구 관계, 차단, 받은 편지 열람·삭제는 별도 상태입니다. 상대를 차단했다고 모든 기존 편지가 삭제되는 것은 아닙니다. 친구 편지와 시스템 편지는 kind와 시설 예외를 구분하고, 우리 섬 채팅방은 별도 저장소를 사용합니다.

탈퇴하면 Data는 같은 트랜잭션에서 그 사용자가 주고받은 편지를 삭제합니다. Realtime은 `user.withdrawn`을 받아 메시지 본문·발신자·클라이언트 식별자를 지우고, 다른 주민의 읽음·페이지 커서가 가리키는 행만 남깁니다(Realtime V4). 메시지 저장도 탈퇴와 같은 사용자 잠금을 거쳐, 탈퇴 뒤 늦게 도착한 쓰기를 거절합니다.

## 신고

`POST /reports`는 게스트를 포함한 로그인 사용자가 사유·상세 내용과 대상(사용자·편지·섬 채팅·공지·공지 댓글·방명록·섬·기타)을 보냅니다. 서버는 세션을 확인한 뒤 접수 번호만 돌려줍니다.

- 같은 요청 키와 같은 본문은 같은 접수 번호, 다른 본문은 409입니다. 계정당 1시간 20건입니다.
- 함께 보낸 대상 ID와 텍스트는 신고자의 진술입니다. 접수가 원본 일치나 위반을 증명하지 않으며, 자동 차단·자동 숨김을 하지 않습니다.
- 운영팀이 내부 경로로 미종결 신고를 읽고 실제 조치 뒤 종결합니다. 재종결은 409입니다. 종결 30일 뒤 매시간 작업이 사건을 파기하고, 적법한 보존 요청이 있으면 사유를 적어 보존합니다(Data V16).

## 사건과 알림

outbox의 커밋, relay 전달, 소비자 수신, 중복 판정, 외부 FCM 요청은 각각 다른 단계입니다. HTTP 성공만으로 알림의 기기 도착을 증명하지 않습니다. 실패·재시도·중복은 사건 ID와 발송 이력을 기준으로 다룹니다.

이동의 lease·epoch와 단체 채팅의 `clientMessageId`는 서로 다른 수명과 보장을 갖습니다. 한 기능의 멱등키를 다른 기능에도 있다고 가정하지 않습니다.

## 이전 도메인 기록

1.x의 `group_challenges`, `bet_sessions`, 개인 시간조각과 리그 정산 결정은 [ADR-009](/adr/adr-009-server-owns-money), [ADR-010](/adr/adr-010-idempotent-settlement), [ADR-011](/adr/adr-011-challenge-bet-two-layers)에 남아 있습니다. 현재 Cattus의 퀘스트·물고기·섬 순위와 같은 상태 머신으로 합치지 않습니다. 건설의 「각자 몫」 정책도 2026-11-09 섬 통장 합산으로 대체된 이전 기록입니다.
