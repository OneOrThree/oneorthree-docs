## 공개 API와 내부 계약

Business는 앱의 공개 HTTP API와 `/screens/*` 조합 응답을 제공합니다. 화면에 필요한 조각을 내부 API에서 받아 공개 DTO로 옮깁니다. Data 엔티티나 내부 응답 DTO를 그대로 공개하지 않습니다.

Data는 제품 권한과 원자 명령을 소유합니다. Business가 형식을 검사해도 주민 자격·섬장 권한·잔액·현재 세션 같은 최종 판정은 Data에서 이뤄집니다. 내부 호출에는 서비스별 토큰과 사용자 컨텍스트를 전달합니다.

## 데이터 소유권

| 데이터 | 정본 | 주요 주의점 |
| --- | --- | --- |
| 계정·섬·집중·물고기·건설·상품·친구·편지 | Data PostgreSQL | 원장·receipt·outbox와의 트랜잭션 경계 |
| 우리 섬 채팅방 메시지 | Realtime PostgreSQL `gromo_chat` | `clientMessageId` 재전송 처리, REST 과거 조회 |
| 알림 사건·발송 이력 | Notification PostgreSQL | 중복 수신과 외부 FCM 성공은 별도 |
| 집중 presence·이동·채팅 fanout | Shared Redis | 전송·표시 상태이며 제품 권한의 정본 아님 |
| 폐기 세션 | Business Redis | 기존 link-preview 캐시는 제거됨 |

## 편지와 채팅

친구 편지는 공개 `/letters`를 거쳐 Data에 저장됩니다. 게스트 발송에는 `SOCIAL_LOGIN_REQUIRED`가 적용됩니다. 수신 목록과 상세 열람의 우체통 시설 판정은 호출자 측 섬 기준이며, 발송 시 상대 섬의 우체통 완공 여부를 검사하지 않습니다. 시스템 편지는 `kind=system`으로 구분합니다.

우리 섬 채팅방은 `/islands/{id}/messages`를 사용합니다. Business가 Data의 주민 자격을 확인한 뒤 Realtime 내부 REST를 호출합니다. 앱의 `useIslandChat`은 화면이 활성화되고 앱이 전경에 있을 때 10초마다 조회합니다. 서버에 legacy STOMP 채팅 경로가 남아 있어도 현재 앱의 단체 채팅이 그 경로를 구독한다고 설명하지 않습니다.

상세 권한·멱등성과 차단 규칙은 [편지·채팅·실시간 권한](/spec/messaging-and-realtime)에 있습니다.

## 사건 전달

Data relay는 대상별 전달과 재시도를 관리합니다. REALTIME 사건은 기본 HTTP, 선택적으로 `realtime-events`를 사용합니다. Notification의 Kafka 사건 경로는 `notification-events`를 사용합니다. 같은 사건의 HTTP·Kafka 수신도 소비자 중복 처리 계약을 따라야 합니다.

`auth.session.revoked`는 Notification뿐 아니라 Realtime에도 전달됩니다. Realtime은 폐기된 sid의 연결을 닫고 재전달을 막습니다. 연결 때 인증했다는 이유로 이후 세션 폐기를 무시하지 않습니다.

## 이동과 재접속

이동 multi-instance 모드는 Redis의 섬 소유권 lease와 epoch로 소유 JVM을 정합니다. 다른 인스턴스의 명령은 소유자에게 전달되고, 프레임은 Redis를 거쳐 참여 인스턴스에 퍼집니다. 소유자는 자신이 만든 프레임도 같은 수신 경로로 처리합니다.

소유권을 잃으면 방을 비우고 발행을 중단합니다. 오래된 epoch 프레임은 무시하고 재입장 시 FullState를 받습니다. 정상 종료 handoff는 짧은 TTL의 Redis 좌표 인계이며 PostgreSQL에 모든 이동을 영구 기록하는 방식이 아닙니다.
