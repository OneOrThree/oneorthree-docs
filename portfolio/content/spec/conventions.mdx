## 코드와 계약

Business는 공개 HTTP와 화면 조합을, Data는 제품 상태와 원자 명령을 맡습니다. 공개 DTO에 DB 엔티티나 내부 전송 DTO를 그대로 노출하지 않습니다. 에러 코드·상태·retryable 같은 클라이언트 분기 계약은 서버와 앱에서 함께 검증합니다.

새 기능은 가까운 구현의 관례만 복사하지 말고 [현재 규약 디렉터리](https://github.com/OneOrThree/phone/tree/af80af04241cefaa33b9f2a1e383548ecc9b10fa/docs/conventions)와 해당 서비스 README를 확인합니다. 레거시와 2.0 계약의 차이를 숨기는 호환 코드를 추가하지 않습니다.

## 데이터와 날짜

시간 저장, 화면의 ‘오늘’, 집중 분 적립일, 주간 집계는 각각의 도메인 계약을 따릅니다. Cattus 물고기는 분이 완성된 UTC 날짜에 귀속합니다. Gromo 1.x의 country-zone 또는 클라이언트 date 규칙을 모든 2.0 도메인에 일괄 적용하지 않습니다.

잔액·정산·현재 주민 자격은 서버가 판정합니다. 중복 요청은 API별 멱등 계약을 사용합니다. 친구 편지에는 단체 채팅의 `clientMessageId` 규칙이 없습니다.

## PR과 운영 승격

일반 변경은 main 대상 PR에서 검토합니다. main → release 승격 PR은 **Create a merge commit**으로 병합해 main 부모 이력을 보존합니다. 과거 fast-forward push·PR close 절차는 대체됐습니다.

승격 리뷰는 기준 SHA와 사용자 기능·수정·운영 변경을 한국어로 요약합니다. 서버·Kafka·Redis의 release 발행과 운영 CD는 별도 단계입니다. V2 버전 스크립트는 patch를 올리며 `release:major/minor/patch` 라벨을 읽지 않습니다.

자세한 규칙은 [AGENTS.md](https://github.com/OneOrThree/phone/blob/af80af04241cefaa33b9f2a1e383548ecc9b10fa/AGENTS.md), [Git·PR 규약](https://github.com/OneOrThree/phone/blob/af80af04241cefaa33b9f2a1e383548ecc9b10fa/docs/conventions/git-pr-conventions.md), [운영 V2](https://github.com/OneOrThree/phone/blob/af80af04241cefaa33b9f2a1e383548ecc9b10fa/docs/engineering/prod-v2-pipeline.md)를 따릅니다.

## 문서 기준

제품 이름은 `CONTEXT.md`, 기능 의도는 PRD·정책·설계, 실제 구현은 고정 커밋의 코드, 배포는 파이프라인과 성공 기록으로 확인합니다. 서로 어긋나면 차이와 근거를 남깁니다. 사이트 설명을 가장 높은 정본으로 두지 않습니다.

기존 기록의 날짜·측정값은 보존합니다. 뒤집힌 ADR에는 대체 상태와 후속 문서를 붙입니다. 긴 문서는 제목 다음에 바로가기 목차를 두고, 실행 방법은 현재 경로로 연결합니다.

## 운영 제약

AWS 부하 테스트 실행·재개와 부하용 데이터 생성은 금지합니다. 과거 측정 기록은 재실행 승인으로 사용할 수 없습니다.

Terraform apply는 저장한 plan을 사용자가 보고 명시적으로 승인한 뒤에만 실행합니다. 의도 밖 변경이나 replace·destroy가 있으면 멈춥니다. 이 사이트의 갱신은 서버 배포·인프라 변경을 실행하는 작업이 아닙니다.
