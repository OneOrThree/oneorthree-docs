## 이번 대조 기준

기준은 [phone main 1281cbfc4](https://github.com/OneOrThree/phone/blob/1281cbfc4559ba3bbe991c8acd529e66257cc5fc/README.md)입니다. 사용자에게 보여 주는 제품 이름은 **Cattus**, 한국어 앱 이름은 **집중할고양**입니다. `GROMO-####`, `catus-*`, `docs/prd/fishcat/` 같은 코드·배포 식별자는 유지합니다.

코드에 있는 기능, 설정 기본값, 배포 기록, 실기기 확인은 서로 다른 근거입니다. 이 사이트의 현재 안내는 코드와 저장소의 운영 기록을 대조한 결과입니다. 운영 호스트를 새로 조사하거나 기능별 운영 성공을 재검증한 것은 아닙니다.

## main과 운영의 차이

| 단위 | 운영에 있는 것 | main에만 있는 것 |
| --- | --- | --- |
| 서버 4종 | `catus-v2.0.14-V2`(release `a579cc1c6`, 11-14 02:32 KST CD 성공). main #1665까지. CD는 바뀐 서비스만 교체하므로 서비스별 태그는 Data·Realtime v2.0.14, Business v2.0.13, Notification v2.0.11 | #1669 잡지 다음 호 홍보 칸 API, #1672 섬 퀘스트 삭제·집중 퀘스트 시간대 겹침 금지(Data V17) |
| 백오피스 | `backoffice-v1.0.9-V2`(11-10). 이후 백오피스 코드 변경 없음 | 없음 |
| Kafka·Redis | `kafka-v1.0.3-V2`·`redis-v1.0.4-V2`(11-02 CD). 11-09의 `kafka-v1.0.5`·`redis-v1.0.6`은 발행 태그만 있고 CD는 돌지 않음 | 없음 |
| 앱 | 최신 출시 태그 iOS `app-2.3.7-ios-14`(11-13), Android `app-2.3.27-android-918`(11-18 머지 자동 빌드). 태그는 빌드 기록이며 스토어 공개와 별개 | #1670·#1673 등은 서버(#1669·#1672)가 운영에 나간 뒤 내보내야 함 |

배포 기록과 순서는 [V2 배포](/operations/06-v2-deployment)를 봅니다. 태그와 CD 성공은 배포 기록이며, 기능별 운영 동작을 새로 실측한 결과가 아닙니다.

## 오래된 기록 읽기

연대기·연구 노트·실험·회고는 당시 문제를 어떻게 해결했는지 보여 주는 기록입니다. 날짜를 오늘로 바꿔 현재 사실처럼 만들지 않습니다. ADR-021의 fast-forward 승격과 ADR-030의 게스트 동일 취급처럼 바뀐 결정에는 대체 상태와 후속 안내를 붙였습니다.

서버 성능 수치는 10월 22일까지 보관한 실험 조건에 한정됩니다. 11월의 앱 실기기 측정은 [성능 기록](/performance)에 따로 있습니다. AWS 부하 테스트 실행·재개와 부하용 데이터 생성은 금지되어 있으며 이번 갱신에서도 실행하지 않았습니다. Cattus 2.0 지표는 11월 중순에 조회한 스냅샷만 싣습니다. 9월의 1.x 주간 분석을 현재 지표로 환산하지 않습니다. 범위는 [그로스 자료의 범위](/growth/current-data-scope)에 있습니다.
